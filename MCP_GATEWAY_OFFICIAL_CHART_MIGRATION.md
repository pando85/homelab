## Critical Migration Issues

### 1. Session Key Incompatibility (BLOCKER - RESOLVED)

**Problem:**
- Current ESO secret has key `SESSION_KEY`
- Official chart expects key `key` (hardcoded in deployment.yaml:86)
- Cannot override via values

**Solution:**
- Updated `templates/session-key-generator.yaml`: `secretKeys: [key]`
- Migration requires deleting existing ExternalSecret and Secret
- ESO will recreate with correct key name on next sync

**Impact:**
- In-flight MCP sessions invalidated (acceptable for foundation with no routes)
- Owner accepted short outage for migration

### 2. Deployment Selector Change (IMMUTABLE FIELD)

**Current selector:**
```yaml
app.kubernetes.io/controller: agentgateway
app.kubernetes.io/instance: mcp-gateway
app.kubernetes.io/name: mcp-gateway
```

**New selector:**
```yaml
app.kubernetes.io/name: agentgateway-standalone
app.kubernetes.io/instance: mcp-gateway
app.kubernetes.io/component: standalone
```

**Impact:**
- Deployment selector is immutable - cannot update in place
- ArgoCD will delete old Deployment, create new one
- Short outage during transition (acceptable)
- Service DNS name unchanged (fullnameOverride: mcp-gateway)

### 3. Service Ports (PRESERVED)

**Current:** 3000 (http), 15020 (metrics), 15021 (healthz)
**New:** 3000 (http), 15020 (metrics), 15021 (healthz)

No change - Service DNS and port numbers preserved. Ingress backend reference unchanged.

### 4. Monitoring: ServiceMonitor → PodMonitor

**Current:** ServiceMonitor (app-template)
**New:** PodMonitor (official chart)

**Impact:**
- Brief monitoring gap during transition (acceptable)
- Prometheus continues scraping same endpoint (15020/metrics)
- PodMonitor has `release: monitoring` label for Prometheus selector

### 5. ConfigMap Name (PRESERVED)

**Current:** `mcp-gateway-config`
**New:** `mcp-gateway-config` (fullnameOverride)

No change - ConfigMap name preserved.

### 6. NetworkPolicy

**Current:** Gated by `networkIsolation: false` (not rendered)
**New:** Chart has no NetworkPolicy templates

**Migration:** None needed - no NP rendered in either case.

## Migration Execution Steps

**Pre-deployment:**
1. Commit whitelist (see above)
2. Push to origin/master
3. Wait for ArgoCD to detect changes

**Deployment:**
1. Delete existing ExternalSecret:
   ```bash
   kubectl --context=grigri delete externalsecret mcp-gateway-session-key -n mcp-gateway
   ```
2. Delete existing Secret:
   ```bash
   kubectl --context=grigri delete secret mcp-gateway-session-key -n mcp-gateway
   ```
3. ArgoCD sync with prune=true (already configured)
   - Old Deployment deleted (selector mismatch)
   - New Deployment created
   - Old ServiceMonitor pruned
   - New PodMonitor created
   - ESO recreates Secret with key `key`

**Post-deployment verification:**
1. Verify new Deployment created:
   ```bash
   kubectl --context=grigri get deployment mcp-gateway -n mcp-gateway
   ```
2. Verify pod starts, Ready 1/1:
   ```bash
   kubectl --context=grigri get pods -n mcp-gateway -l app.kubernetes.io/component=standalone
   ```
3. Verify ESO secret created with key `key`:
   ```bash
   kubectl --context=grigri get secret mcp-gateway-session-key -n mcp-gateway -o jsonpath='{.data}' | python3 -c "import sys, json; print(list(json.loads(sys.stdin.read()).keys()))"
   ```
4. Verify Service DNS resolves:
   ```bash
   kubectl --context=grigri run -it --rm debug --image=busybox -- nslookup mcp-gateway.mcp-gateway.svc.cluster.local
   ```
5. Verify Ingress routes (404 expected, no backends):
   ```bash
   curl -I https://mcp.grigri.cloud/
   ```
6. Verify TLS valid:
   ```bash
   curl -vI https://mcp.grigri.cloud/ 2>&1 | grep "SSL certificate verify ok"
   ```
7. Verify no NetworkPolicy:
   ```bash
   kubectl --context=grigri get networkpolicy -n mcp-gateway
   ```
8. Verify PodMonitor created:
   ```bash
   kubectl --context=grigri get podmonitor mcp-gateway -n mcp-gateway
   ```
9. Wait 180s stable window
10. Capture UTC timestamps for deployment completion
